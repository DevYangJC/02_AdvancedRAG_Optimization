# 安全审计技能（security-audit）

## 四个检查维度

### ① 敏感信息泄露 —— 脚本扫描 + 人工确认

- **脚本客观数据**：运行 `node scripts/security-scan.js [路径]`，静态扫描硬编码敏感信息（已适配支持 .py）
- 脚本分级：🔴 HIGH（私钥块/JWT/云厂商密钥/高熵值，需立即处理）｜🟠 MEDIUM（敏感命名硬编码，需人工确认）｜🟡 INFO（占位/测试值）
- 退出码 1 = 存在 HIGH/MEDIUM，属预期信号
- 脚本报告的每一处命中，**人工阅读确认**：是真密钥？是测试值？是否该移到环境变量？
- 注意：`backend/.env` 含真实 API Key 但已被 .gitignore 排除（脚本已豁免该文件）；确认 `.env*` 未被 git 跟踪

### ② SQL 注入等注入风险 —— 语义审查

检查所有数据库相关代码（重点 `backend/app/db/`、各 `services/*_service.py`、`tasks/ingestion.py`）：

- [ ] 所有查询是否使用 **SQLAlchemy 预编译机制**（`select().where()`、参数绑定），有无字符串拼接 SQL（`f"... WHERE a='{value}'"`）
- [ ] `like` 模糊查询的关键字是否处理通配符（`%`、`_` 注入）
- [ ] 动态表名/列名是否白名单校验（标识符不能走参数绑定）
- [ ] API 入参是否经 Pydantic 校验后再进查询（类型/长度/枚举白名单）

### ③ 配置文件明文敏感信息 —— 静态检查

- [ ] 是否存在 `.env*` 文件；若存在，是否被 `.gitignore` 排除（未排除 = 可能已提交到仓库）
- [ ] 配置文件（vite.config、requirements.txt、CI 配置）中是否有明文密码/密钥/证书
- [ ] `JWT_SECRET` 是否为强随机值（生产环境禁止默认值）；种子管理员密码是否可被环境变量覆盖
- [ ] 依赖版本漏洞：前端 `npm audit --omit=dev`；后端 pip 依赖检查（网络不可用则说明跳过）

### ④ 其它安全隐患 —— 语义审查清单

**FastAPI/后端特有（重点）：**
- [ ] **JWT 配置**：`jwt_secret` 强度、算法白名单（HS256 固定）、token 类型区分（access/refresh 不可混用）
- [ ] **密码存储**：bcrypt 加盐哈希（禁止明文/弱哈希）；登录失败不区分「用户不存在/密码错误」（防枚举）
- [ ] **上传安全**：扩展名白名单校验、文件以 uuid 重命名落盘（防路径穿越 `../`）、大小限制
- [ ] **越权**：所有会话/文档查询是否带 `user_id` 归属条件（水平越权）；admin 接口是否校验 role（垂直越权）
- [ ] **CORS**：生产环境允许的源是否收窄；开发代理是否只监听本机
- [ ] **限流**：登录/注册/问答是否有限流（slowapi），防暴力破解与成本滥用
- [ ] **SSE/流式**：对话接口鉴权是否在流开始前完成（防未授权消耗 token）

**通用风险：**
- [ ] `eval` / `exec` / `subprocess` shell 拼接（应使用参数数组）
- [ ] 路径穿越：文件读写是否拼接用户输入；`Path` 操作前是否净化
- [ ] 用 `random`/`Math.random()` 生成安全敏感值（应使用 secrets/crypto）
- [ ] `console.log`/日志是否可能输出敏感数据（token/密码/完整查询参数）
- [ ] 前端 localStorage 只存 token，不存敏感业务数据；XSS 面（`v-html` 使用是否受控）

## 参数说明

| 参数 | 行为 |
|---|---|
| （无参数）或 `--all` | 审计全项目 |
| `<路径>` | 只审计指定文件/目录（可多个） |

## 执行流程

1. **静态扫描（脚本）**：`node scripts/security-scan.js [路径]` 获取敏感信息清单。
2. **依赖审计**：前端 `npm audit --omit=dev`（如网络不可用则说明跳过）；后端 pip 依赖人工检查关键包版本。
3. **语义审查**：按上表逐项检查 ②③④，阅读相关文件确认。
4. **汇总报告**：按「报告格式」输出，逐条给出 位置 + 风险等级 + 依据 + 修复建议。
5. **发现问题的处理规则**：
   - 发现**真实密钥泄露**：立即提醒用户轮换该密钥，并建议移入环境变量/安全存储；
   - **需要修复代码**时：按 CLAUDE.md「方案决策规则」列出修复方案等待用户选择，不擅自改代码；
   - 确认安全的条目在报告中明确标注「已确认安全」，避免噪音。

## 报告格式

```text
### 安全审计报告（YYYY-MM-DD HH:mm）
- 扫描文件 N 个（静态脚本）| npm audit：X 个漏洞（高/中/低）
- 🔴 高危 M 处：文件:行号 | 问题 | 依据 | 修复建议
- 🟠 中危 K 处：文件:行号 | 问题 | 依据 | 修复建议
- 🟡 低危/提示 J 处：文件:行号 | 说明
- ✅ 已确认安全项：② SQL 注入…/ ③ 配置…/ ④ 其它…（逐项列出）
- 结论：总体风险评级（低/中/高）+ 优先处理建议
```

## 规则

- 涉及修复方案选择按 CLAUDE.md「方案决策规则」执行；本技能只审计与报告，不擅自修改代码。
- 脚本扫描结果与人工确认不一致时（误报/漏报），以人工阅读为准，并在报告中说明。
- 真实密钥泄露（HIGH）按「立即提醒轮换 + 建议迁移」处理，不打印密钥原文（报告一律脱敏）。
- 新增安全规则/工具选型属于技术方案，需列方案等用户选择。
